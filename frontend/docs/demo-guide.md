Use the actual frontend on port 5173 and existing FastAPI backend on port 8000. Start from the README. Set aside unique demo codes/numbers, and use the IDs returned by your own API; do not assume an example ID exists. Test data is synthetic.

## Questions to practice

- Where is the API base URL configured, and when is it included in the build?
- How does a request receive the bearer token?
- Why did we choose sessionStorage, and what are its security limitations?
- How does `/auth/me` establish the displayed identity?
- Which part of the code clears an expired session?
- Why must the backend reject a forbidden request even if the UI hides its button?
- How do page and filter controls become query parameters?
- Why do selectors paginate instead of assuming the first 20 records are the whole database?
- How are server field errors associated with inputs?
- Why does a request returning 204 need different JSON handling?
- Why are duplicate enrollments and foreign-key rules still checked by the backend?
- How is the displayed list refreshed after a mutation?
- What happens when a stale search request finishes after a newer request?
- Which implementation decision would you change, and how would you test it?
