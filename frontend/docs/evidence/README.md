Core data, authentication, validation, ownership and CRUD checks use the actual API. Playwright deliberately injects delayed responses, a failed network request and a synthetic HTTP 500 for failure-state checks; those screenshots demonstrate frontend behavior under controlled faults, not a claim that the real server unexpectedly failed.

Automated results are stored one directory above in `unit-test-results.txt`, `e2e-results.txt` and `build-results.txt`. Backend regression evidence is in the project root's `docs/test-results.txt`. Browser traces and HTML reports are ignored because they may contain temporary session credentials.

Verified results: **16 frontend unit/component tests, 7 browser integration scenarios, and 22 backend regression tests passed**. The browser suite also proves that the registrar has no grade access while still reading a transcript with a computed GWA. Production login, nested-route refresh and logout passed against the development API; see `../production-smoke-results.txt`.
